## Real pushback

**1. This reopens two things `ROADMAP.md` already settled, without a specific problem forcing
the reopen.** That doc's own reasoning was direct: *"Not a demo, not a web port with a wrapper
around it"* and *"two independent, platform-appropriate implementations of the same proven
feature set is a reasonable choice here, not technical debt."* The new doc's Phase 1 puts the
shared-codebase question back on the table (React Native Web / Expo Router web target) as
something needing "an actual answer," not just revisited framing. For a personal instrument built
for an audience of one, the case for shared-codebase infrastructure is *weaker* than it would be
for a team product — there's no second developer benefiting from the reuse, and it's real
architectural risk (React Native Web has genuine compatibility gaps with vanilla DOM/canvas work,
which is most of what `index.html`'s ouroboros/EKG rendering actually is) for a benefit that's
mostly aesthetic ("one codebase" is nice, not load-bearing). **I'd want a concrete reason this
question needs reopening now, not just that it's open in principle.**

**2. "Archive/tag `index.html` as prelude to rebuild" is listed as an immediate, no-blocker
action — but it's actually the highest-stakes item in the whole doc, not the lowest.** Everything
else on the "start now" list is mechanical and reversible (an npm install, a config check). This
one is the first real step toward modifying a **live, working, personally-used app** — the doc's
own words: *"a real instrument Bonesaw uses himself... real history in it."* I'm not doing
anything to the live web app on the strength of a handoff doc alone, however detailed. Tagging the
current state for safety is genuinely low-risk by itself — but I'd want that confirmed directly
by you, here, before I touch anything upstream of a currently-working personal tool, separate from
whatever's already been decided in the other conversation.

**3. Provenance question, stated plainly rather than left implicit.** This doc represents itself
as relaying decisions from a separate chat. I don't have independent confirmation those decisions
are exactly as intended, or whether anything got extrapolated further in the telling than you'd
actually said. Given this changes real priority (Play Store work — the thing we spent a full
session building a milestone plan for — explicitly deprioritized) I want that confirmed by you
directly, not inferred from the doc's own confidence about itself.
